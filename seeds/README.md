Held-out checks are single-use: a task's held-out checks are published in its scorecard when the task is judged, so never post the same seed twice.

A seed is a folder: `task.json` (reward, token, windows, winners, verifier), `brief.json`, `criteria.json`, `solution.txt` (a correct answer) and `weak.txt` (a plausible, flawed one). Those are public. A seed whose `criteria.json` says `has_heldout: true` also has held-out checks, and those are **not in this folder**. A rubric seed has no held-out checks: a model scores it against the public criteria, so there is nothing to keep back, and `criteria.json` says `has_heldout: false`. Rubric seeds are open tasks (no cap on entries); the Judge grades the first 50.

## Where the held-out checks are

The checks are secret until the task is judged, so they are never committed. They live in a private directory, one file per seed: `<private dir>/<slug>/heldout.json`. The swarm demo's pack (`scripts/swarm-research-pack/`) keeps its checks in the same directory, under `swarm-research-pack/parent/heldout.json` and `swarm-research-pack/children/<slug>/heldout.json`.

- The private directory is `$TENDER_SEEDS_PRIVATE_DIR` when that is set (in the shell, or in `.env`; the shell wins). Otherwise it is `seeds-private/` of the repository, which `.gitignore` and `.dockerignore` leave out. A leading `~/` is the home directory.
- Nothing that reads a held-out file reads it from `seeds/`. `seeds.test.ts` fails if a `heldout.json` appears in a seed's folder.
- `pnpm seed`, `pnpm demo:local` and the swarm demo (`pnpm exec tsx scripts/swarm-demo.ts`) read the checks from the private directory. A seed whose file is not there stops the run before anything is posted, with `held-out for <slug> not found in <dir>; set TENDER_SEEDS_PRIVATE_DIR`: a task is never posted without its checks.
- The tests that score a seed against its checks (the solution passes, the weak and the known-wrong answers do not, the key checks every value) run when the private directory has the file, and are skipped when it does not, which is every clean checkout and CI. The tests that read only the public files run everywhere: the schemas, the rubric rules, the counts (30 seeds, 25 with checks, 22.50 tUSDC), the briefs and criteria. A private directory that holds some of the files but not all is an error, not a skip.
- Tests that only need a task to have checks (posting the thirty seeds to a local chain, the lead agent's sub-tasks) use stand-ins of the right kind from `synthetic-heldout.ts` when the real ones are not there. A stand-in scores nothing in earnest.

`seeds.test.ts` scores every seed with the Judge's own scorers. A rubric seed is scored by the real rubric scorer against a fake model server that grades by a few plain checks (`rubric-stand-in.ts`). That shows the rubric can tell the solution from the weak answer, and that the pass mark (85 on every rubric seed) stops an entry that loses one core element of the task: the tests take each such element out of the solution, and take each heavy criterion out alone, and check that the score falls below the pass mark. It does not show how a real model grades.
